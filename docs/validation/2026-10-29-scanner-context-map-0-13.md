## Implemented outcomes

- An explicit protective clause no longer exempts a later disclosure command.
  Protective/topic observations stay visible; actual sensitive identifiers remain
  independently actionable. Literal quoted examples and scoped prohibitions have
  paired controls rather than broad paragraph exemptions.
- `read_pattern: chunked-reference` alone is a recognized reading declaration,
  not a promise of a physical EOF marker. Explicit EOF claims still require
  filename-bound, true-end, outside-fence verification. No declaration establishes
  runtime reading, complete coverage or safety.
- Selecting a box emphasizes its incoming/outgoing connections and dims others
  in both views. Optional filtering, clearing and keyboard equivalents preserve
  all original data. Existing test-path highlighting remains independently visible.
- Source kinds, resolution, runtime uncertainty and unassessed trust/sensitivity
  have separate explanations. Complete diagram evidence and map exports remain
  available; imported maps preserve saved and in-memory drafts.

## Scope and limitations

Research: [primary-source review and comparison protocol](../research/2026-10-29-scanner-quality-evidence.md).
The previous external 180-case corpus is exposed diagnostic material; it was not
reclassified as a fresh holdout. No external comparator was run. Authored tests
cannot establish general recall, false-positive rate or industry leadership.

Browser tests use authored synthetic inputs. The real local API checks exercise
the candidate application, not production client-certificate access. Dense graph
routes may still cross; connection focus improves navigation rather than proving
optimal layout. Runtime execution, approval enforcement, output quality, manual
screen-reader use and human acceptance are unverified by these checks.
